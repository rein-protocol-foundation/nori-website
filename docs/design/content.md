## 核心定位

**Nori 是一个能够持续承担组织职责的 super agent。** 一个 Nori 通过多个数字分身或下属 subagents，协调人员、运营、治理、资源、社区与对外关系；不是多个无关的 peer agents，也不是五名真人雇员。首要受众为 nonprofit／NGO 负责人、运营团队与董事会，其次是贡献者。

价值由具体工作体现：接住持续职责、主动跟进承诺、跨工具完成任务、连接适用服务、保留可接续背景。专业服务和重大决策仍受组织制度、服务能力与人员权限约束。营销描述不作为集成验证，构造案例不作为真实组织历史、交易、客户评价或成果数字。

Nori 公共仓库 README 当前说明许可证尚未选择。因此用 `super agent`、`public code`、`built in the open`，不把代码可见表述为已授予开源许可。来源：https://github.com/rein-protocol-foundation/nori-agent 。README 同时说明完整范围仍在开发，真实支付、资金预留、自动角色授予及完整活动到发布流程未启用。

## Work · One request. Work moves everywhere.

三个不同应用场景按阅读顺序直接展示，保留真实密度与任务背景，不重复三个相同聊天窗口。

1. **Slack onboarding**：Maya 周五休假，Alex 周一入职，Sam 接续权限检查与入职介绍。标题 `A new teammate. A ready first day.`；保留频道父消息和独立 thread pane，展示 signed offer 已关联、Sam 周五验证权限、周一 10:00–10:30 orientation、开放的 GitHub onboarding issue。背景和工件可以接续，不展示证件或私密员工材料。
2. **Lark tool access**：标题 `The right access. Already in reach.`；Alex 申请 design-tool editor seat，Nori 找到已有 license 可重新分配，无需新增采购；申请已记录，Maya 的负责人批准待处理。批准和配置后才验证登录与编辑，状态不提前标为已获访问。展示原生申请、审批与验证工件。
3. **Google Docs / Calendar board work**：标题 `The decision becomes the next step.`；Docs 的 Q4 会议包展示 Workshop scope 待决策及已附预算审阅、Contributor coverage 与 Previous commitments；Calendar 为周四 2:00 PM review。Nori 说明决定后连接负责人和下一期限，不伪造投票通过。

更广泛的人事、采购、跨国雇佣、差旅、payroll、签证与专业服务属于产品方向，不在本轮主画面扩充成已验证功能清单。组织政策约束选型、采购和后续执行。

## Finance · A message becomes a financial workflow.

主视觉是一项连续任务：**iMessage 请求 → Stripe 草稿 → owner review → ledger**。

示例 `INV–014 / Workshop registration`：iMessage 请求四个 workshop places，每个 $60，总计 $240 USD。Nori 准备 Stripe invoice Draft 并关联活动，交 Maya owner review；Sending is not yet authorized，Project ledger 标示 Awaiting review。金额、人物和状态均为 sample data，不制作假支付成功回执，不声称当前能 live payment。

资金模型保留组织储备、项目预算、工作资金三层：储备独立保管，项目资金按用途安排，工作资金有基础设施执行的限额。Nori 不得自提限额、无限补款或绕过权限。此为 planned workflow／产品设计，不能当作已验证的资金控制。

金融基础设施通过三个具体工作案例解释，一处 `Planned workflows` 说明覆盖尚未接通的流程，不再逐卡罗列术语：

1. **Blockchain / Safe**：为 workshop 贡献者准备 **300 USDC 津贴**。Nori 把用途、贡献者与 workshop budget 关联，生成 Safe 转账提案，等待 **2 of 3 signers**；画面不显示已经转出，不使用真实钱包地址。
2. **Bank / ACH**：收到 **$480 场地账单**，该用途已批准预算为 **$600**。Nori 核对账单与收款对象，准备 ACH payment，交负责人审核；显示拟支出后预算余量 **$120**，明确这是 budget remaining，不是银行余额。不展示已提交或到账。
3. **Stripe / PayPal**：**四个 $60 报名名额，共 $240**。延续 INV–014 的 Stripe invoice draft，并以按渠道归类的报名记录说明对账：Stripe 和 PayPal 的记录关联到同一活动账本，待审状态可见；草稿不能算入实际到账，也不杜撰手续费或结算金额。

每个案例明确「收到什么 → Nori 做什么 → 交付什么」，使用可读的交易提案、付款审核或报名账本工件。其余托管、保险、会计、募资与店铺服务保留为未来可探索方向；品牌出现不意味着伙伴关系或已接通。

## Community / software · Feedback comes in. Better software comes out.

连续故事：**Discord feedback → GitHub issue → PR → checks → maintainer review → report / monitor**。

Discord 中 Alex 报告 checkout retry 导致两封 confirmation emails；Nori 定位 repeated event，创建 issue #142，准备 idempotency check 与 regression test。样例 PR #143 展示 Alex approved、四项 checks 通过及 Merged，关联关闭 #142。后续条列 Develop / Accept / Report / Monitor；样例合并不代表实际发布、真实产品结果或问题永久解决。

Nori 可以识别需要人类专业帮助的工作、组织自愿贡献或提出有范围和验收标准的付费协作；付费任务需要组织预算授权，结算不在本轮伪装完成。保留 one Nori 贯穿反馈、代码和回报，不写成多个 peer agents 开会。

本节以 `Built for around-the-clock contribution` 表达持续协作的设计目标，由 qualified contributors 引导 Nori 从反馈到发布。

Discord 使用 server／channel／member 结构，GitHub 使用 issue／PR／checks／review 结构；两者不是统一聊天模板。示例不包含私人 Slack／Discord 记录或运行记忆。

## Outreach · One project. A voice for every channel.

三个不同工件：**X 原创帖与 reply、Instagram 竖屏创意、Gmail draft**。原创说明项目，reply 回应有上下文的问题；不生成名人假回复、假背书或互动数字。Instagram 展示完成度高的活动视觉，不出现 SVG preview、demo、concept 或实现技术说明；这是页面内的 sample content，不声称已发布真实视频，也不虚构音轨。Gmail 保留草稿状态，正文精简为两段，加 Nori 签名、附件与 Send 操作行；所有内容完整可见，不使用内层滚动区。

同一任务可形成招募、讨论、片段和支持者沟通，避免机械复制到每个平台。真实发帖、发信、视频发布均不在本轮网站实现授权内。

## Continuity · New conversation. Same context.

以 **新问题 → 找到来源 → 连接背景 → 准备下一步** 展示。Maya 问「What should we send our supporters next?」；Google Docs 记录 workshop 主题「when an agent should ask a person」，Slack 交接给 Sam，日历约定 December 3 更新。Nori 的回答逐条关联 01／02／03 来源，并准备 Sam’s supporter briefing。动画依次强调来源、沿连接线汇入 Nori、点亮答案引用及下一步；正文始终可读，减少动态显示完整静态结果。离屏和页面隐藏暂停。不声称任意渠道自动共享全部组织记忆。所有记录为构造材料，并遵守来源权限。
