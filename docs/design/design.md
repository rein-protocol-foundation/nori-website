# Nori — Design

当前有效设计约束 · 2026-11-12。业务内容见 [content.md](content.md)。这两份文件替代历史设计说明；旧稿仅在 [ZIP 归档](../archive/design-history-2026-11-12.zip) 中，正常开发不解压、不批量读取。当前网页实现仍在修订，不作为已认可的设计标准。

## 1. 视觉方向

- 黑白高对比基底，清晰标题、克制留白，工作产物是视觉主体；色彩来自 Nori 角色及原生软件。允许纯黑、纯白；不因通用 skill 改成品牌染色背景。
- 首屏简洁且有产品解释力；03–06 为主要业务段，运营与金融同等重要。各节依据内容决定高度、密度和构图，不重复整屏模板或相同三列卡片。
- 展示具体工作：请求、判断、执行、产物和状态变化。保持原软件比例、信息结构与文字密度；不把软件缩成难读的小窗，也不把图标和短句放大成假 UI。
- 主工件与辅助工件有前后层次：轻透视、浅阴影、少量边缘遮挡。重要文字不能被盖住；不要软胶厚边、卡片套卡片、巨大人物陪衬或装饰流程箭头。
- 字体、间距、宽度、圆角与阴影在视觉定稿后形成少量共享 tokens；已有 Manrope 可作为起点，不将被否定实现的参数视为锁定标准。

## 2. 品牌与素材

- 保留 Nori 猫耳、发型轮廓、胶囊眼睛、天线/耳机，主身份为薄荷绿＋粉色。职位变体大胆用金、蓝银、紫、铜红、深青等发色。
- 普通位置只用头部。半身照仅用于实体员工工牌：透明卡套、黑挂绳、金属扣、清晰职位与组织名；不用 Manager 或部门分类名代替职位。
- 复用认可素材；检查裁取边缘、清晰度及宽高比，不拉伸头像。工牌职位、职责和网页正文使用真实 HTML，不能直接把整张概念图当网页。
- 软件品牌使用可追溯的准确图标；软件画面根据可靠的原生 UI 参考制作局部 HTML 工件，或采用获授权、脱敏截图。来源旁注明素材属性即可，不编造集成认证。勿用通用分支图标冒充 GitHub 品牌或凭记忆重画 logo。
- 概念图只指导构图、身份和层级，其生成式软件细节不是精确 UI 依据。优先使用现有素材，不为调用 skill 重生成整套设计。

## 3. 交互与响应式

- 核心内容全部直接展示。没有 Tab、Drawer、角色切换、点击展开、折叠案例、View case 或跳转装饰箭头。旧图中的这些元素一律忽略。
- 导航、Discord/GitHub/试点 CTA 是真实链接；演示中的发送、支付、登录不是实际业务操作，不做假按钮诱导点击。
- 桌面可有克制的层次与微动；不靠 hover 才显示信息，不自动漂浮、不改变布局占位，不给静态工件假交互暗示。
- 移动端按故事顺序平铺，取消倾斜/重叠；保持文字可读，不以裁掉内容解决拥挤。reduced-motion 取消位移，内容完整。
- 语义标题、可见焦点、键盘导航、合理对比度；尽可能保留无 JavaScript 的正文阅读。

## 5. 实现与验收

- 沿用现有 React / TypeScript / Vite。`src/app` 只组合页面；`src/sections` 按章节组织；品牌、导航与确有共性的工件放 `src/components`；全局 tokens 放 `src/styles`。不把全页写进一个入口，也不让万能卡片决定业务表达。
- 每次只处理授权章节及必要共享组件；保留其他人的修改。读取发生截断时分段补齐，不把命令成功当成读完。
- 项目约束优先于通用设计 skill；只加载当前任务需要的指导，不叠加互相冲突的风格规则。当前工作不要求读取历史 ZIP。
- 每节完成后对照本节内容和设计图，检查真实桌面/移动端截图：故事完整、软件可信、比例正确、没有遮挡或重复模板。仅出现业务关键词不算完成展示。
- 最后分别报告视觉/内容检查和工程检查。构建、链接、资源、响应式、键盘与无障碍通过不等于设计通过；无实测结果不得宣称行为已验证。部署与域名迁移另行授权。
